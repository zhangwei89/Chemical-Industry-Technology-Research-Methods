# 写作约定

## 一、读者画像

**主读者**：化工企业一线研发工程师（25-40 岁，本科或硕士为主）。

画像特征：

1. 有 2-10 年实操经验，熟悉本专业的常规工艺与设备，但对跨专业方法论（DOE、TRIZ、LCA、HAZOP 等）接触碎片化。
2. 日常工作被项目节点压着，最反感两类文字：(1) 学术综述味的八股；(2) 心灵鸡汤味的空洞口号。
3. 真正想看的是：**别人的项目踩过什么坑、用了什么工具、为什么这么选、可以照着做哪几步**。
4. 偶有研究生读者（约 20% 比例），他们更需要方法论框架与参考文献索引。

## 二、风格基线

- **口吻**：高级工程师/项目经理的口吻，平视读者，不端着也不油腻。
- **句长**：中长句为主（20-40 字），关键判断用短句强化。
- **段落**：每段 3-6 句，论点-论据-例子三件套完整。
- **术语**：第一次出现给中英文全称与缩写，之后只写缩写。
- **数字**：能用数字量化就别用形容词（"显著提升" 改 "选择性从 78% 提升至 92%"）。
- **避免**：
  - "在当今时代""随着科技发展""不言而喻"等空话；
  - 一段话引用三次同一篇文献的堆砌；
  - 把读者当外行的"科普化"解释；
  - 网络梗、口语化过度。

## 三、章节结构模板

```
# 第 N 章 {章名}

> 本章核心问题：一句话点明本章要解决的最关键问题。
> 学习目标：读完本章，读者应该能做哪 3-5 件事。

## 开篇引子（150-300 字）
用一个真实场景/痛点/反直觉判断切入，引出本章主题。

## 1.1 {节标题}
### 核心问题
### 方法与工具
### 典型化案例
### 常见坑

## 1.2 {节标题}
...（按需 6-8 节）

## 本章小结（300-500 字）
用 5-8 条要点回扣开篇核心问题。

## 思考题
3-5 题，结合本章方法论让读者练手。

## 参考文献
GB/T 7714 格式，5-15 条。
```

## 四、配图规范

1. **必配图的位置**：每个核心方法/工具/对比表至少 1 张图。
2. **编号格式**：图 X-Y（X = 章号，Y = 章内序号），表 X-Y 同理。
3. **实现方式**：
   - 优先 mermaid：流程图、序列图、状态图、甘特图、矩阵图、思维导图。
   - 复杂示意图用 SVG：放 `05_图表_SVG/`，文件名 `fig_X_Y.svg`，正文用 `![图 X-Y 标题](路径)` 引用。
   - 简单对比用 markdown 表格。
4. **图注规范**：图下方必须有图题 + 一句话解读。

## 五、案例规范

> **典型化案例 X-Y**（出处类型：行业公开资料 / 公开专利 / 公开论文 / 工业实践常识）

要素：

- 背景（产业背景、企业类型、生产规模，1-2 句）
- 问题（卡在哪一步，1-2 句）
- 解法（用了什么方法/工具/路径，2-3 句）
- 结果（量化指标，含失败教训，2-3 句）
- 启示（这条案例对一线工程师的可借鉴点，1-2 句）

严禁编造具体公司名称、产品牌号、专利号等不可查证的细节。如果用真实公司，必须是该信息已在公开渠道广泛报道的（如万华 PO/SM 装置、中石化催化剂、巴斯夫 HPPO 等）。

## 六、引用规范

采用 GB/T 7714-2015 顺序编码制。

文内：`xxx 方法[1]`，`xxx 已被广泛研究[2-5]`。

文末参考文献条目（5-15 条/章）：

```
[1] 作者. 题名[J]. 刊名, 年, 卷(期): 起页-止页.
[2] 作者. 题名[M]. 出版地: 出版社, 年: 起页-止页.
[3] 标准编号 标准名称[S]. 出版地: 出版社, 年.
[4] 申请人. 专利名称: 专利号[P]. 公开日期.
```

优先引用：(1) 综述性论文；(2) 行业权威标准；(3) 经典专著；(4) 5 年内的高被引论文。

## 七、自检三关

每章交付前过：

1. 术语一致性：本章新出现的术语是否进了 `02_术语表.md`？前后用法是否一致？
2. 逻辑闭环：开篇核心问题 → 各节回答 → 本章小结回扣，是否扣题？
3. 引用规范：文内引用与文末条目是否一一对应？格式是否正确？

## 八、字数与节奏

- 总字数：全书目标 25-35 万字（不含图表/引用块）。
- 章节字数：每章 7000-9000 字（系统教材档位）。
- 节字数：每节 800-1500 字，平均 1000 字左右。
- 节数：6-8 节/章为宜，过少则单节过长（>2000 字要拆），过多则碎片化。

## 九、禁止清单

- 不得把作者写成"我"，改为"我们"或"工程师"。
- 不得出现空泛的"未来可期""值得期待"。
- 不得在主体里大段罗列本科教材级别的概念定义。
- 不得使用 emoji（除目录标记 `[x]` 等）。
